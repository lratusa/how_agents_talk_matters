# Archiving the raw dataset on Zenodo

The 1.1 GB `data/` directory is the project's primary scientific asset: the
complete raw record of ~140k API calls. It is gitignored (too large for
GitHub) and must be archived separately. [Zenodo](https://zenodo.org) is the
recommended home: free, DOI-minting, and integrated with GitHub.

## Why bother

- Every number in the paper becomes recomputable from primary evidence.
- The cached initial-answer sets let other groups test **new** pairing,
  review, or repair methods with **zero API cost** — this is the most
  likely way the project gets extended and cited.
- A dataset DOI is independently citable; data citations link back to the
  paper.

## What to package

```
data/runs/            # per-run JSONL: initial answers, reviews, syntheses,
                      #   token usage, latency, question IDs, seeds
data/cache/           # bge-m3 embeddings (sha256-keyed) and distance matrices
data/benchmarks/      # exact benchmark snapshots used (check licenses below)
```

Suggested archive layout (one `.tar.gz` per benchmark plus one shared
embeddings pack, or a single zip if you prefer):

```
fprr_mmlu_pro_runs.tar.gz     # 3 seeds x 500 questions, all conditions
fprr_supergpqa_runs.tar.gz    # 4 seeds x 500 questions, all conditions
fprr_embeddings_distances.tar.gz
README_DATASET.md             # schema documentation (write this first)
```

Before uploading, write a short `README_DATASET.md` documenting the JSONL
schema (field names, condition codes C0–C9, seed convention, distance IDs
D1–D4). Copy the relevant table from `preregistration.md` — do not invent
new field names.

## License checklist for benchmark snapshots

- **MMLU-Pro** — check the license of the exact snapshot you used before
  redistributing; if redistribution is not permitted, upload *question IDs
  only* plus a fetch script.
- **SuperGPQA** — same check.
- Model outputs generated by you are yours to share.

If in doubt: archive `data/runs/` and `data/cache/` (your own records), and
for benchmarks provide IDs + download instructions instead of the data
itself.

## Steps

1. Create a Zenodo account (GitHub login works).
2. **New upload** → upload the archives → fill metadata:
   - Title: `FPRR raw experiment records: MMLU-Pro and SuperGPQA`
   - Upload type: Dataset
   - License: CC BY 4.0
   - Related identifiers: link the GitHub repo (`isSupplementTo`).
3. Publish → copy the DOI.
4. Back in this repository:
   - add the DOI to `CITATION.cff` (`identifiers:`),
   - replace the placeholder in `README.md` → *Data availability*,
   - commit.

## Optional: GitHub ↔ Zenodo integration

If you want every GitHub *release* to automatically mint a DOI for the code
itself (separate from the dataset DOI): Zenodo → GitHub tab → flip the
switch for this repository → create a GitHub release. The code DOI and the
dataset DOI serve different purposes; the dataset one matters more here.
